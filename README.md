# Mortgage Analytics Hub  — аналитика ипотечного рынка

Исходный проект пользователя v0.4 сохранён и модернизирован до  для **пилотного банковского внедрения**. Конкурсное решение для раздела «Аналитика» портала «Своё Жильё». Данные: только открытая официальная статистика Банка России и явно помеченные демонстрационные фикстуры. Никаких персональных кредитных данных система не хранит. Проект **не прошёл банковскую приёмку, аудит безопасности или нагрузочные испытания** и не заявляется сертифицированным банковским ПО.

## Возможности

- API `GET /api/v1/series`, `/observations`, `/summary`, `/regions/*`, `/exports/observations.csv`; Swagger при локальном запуске (`/docs`).
- Загрузка ежемесячных федеральных обзоров ЦБ и региональных официальных XLSX с проверкой структуры, даты, значений и происхождения.
- Подключение к документированному [REST Data Service Банка России](https://www.cbr.ru/statistics/data-service/APIdocumentation/) через каталог `/publications`, `/datasets`, `/measures`, `/years` и `/data`. **Идентификаторы Data Service для автоматического импорта должны быть проверены и явно записаны** в `config/targets.json`; произвольные ID не используются.
- PostgreSQL/SQLite, уникальность комбинации ряда и месяца, идемпотентный импорт, отдельный журнал успешных/ошибочных попыток, сохранение последнего корректного набора при сетевых проблемах.
- Интерактивная аналитика Plotly, региональные рейтинги, сравнение регионов, экспорт CSV/PNG, эвристическое прогнозирование на 1–6 месяцев с проверкой на исторических данных.
- Система качества данных: `GET /api/v1/data-quality` — полнота, пропуски в ежемесячных рядах, устаревшие ряды, офлайн-снимки, сравнение итогового показателя выдач федерального обзора с региональной таблицей после перевода `млн руб. → млрд руб.`. **Расхождение выше 2% — сигнал для проверки, а не автоматическое исправление.**
- Журнал доказательств: `GET /api/v1/source-artifacts` показывает SHA-256 успешно импортированных источников и тип получения (онлайн/локальный кэш/ручной снимок); административный `/api/v1/admin/revisions` показывает старые/новые значения после корректировок статистики.
- Отдельный месячный планировщик: 5-е число месяца с 08:00 UTC; при неуспешной загрузке — повтор не чаще одного раза в 6 часов. PostgreSQL advisory lock защищает от запуска двух конкурентных scheduler-процессов; дополнительная история выполнения хранится в `sync_runs`.
- Разделены публичное чтение и административный запуск импорта, ограничены размеры сетевых ответов и XLSX-пакетов, защищены внутренние тексты ошибок.

## Быстрый запуск для конкурса (Windows/Linux, Python 3.11+)

В каталоге с `app/main.py`:

```bash
python -m venv .venv
# Windows PowerShell: .venv\Scripts\Activate.ps1
# Linux/macOS: source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m pytest -q
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте <http://127.0.0.1:8000/>. База SQLite создаётся автоматически. **В v0.5 автоматическая сетевая синхронизация при открытии веб-приложения отключена по умолчанию**, чтобы браузер и API не запускали непредсказуемые фоновые операции. Изначально БД пуста, это нормально. Для первого заполнения выполните:

```bash
python -m app.cli sync-regions-online
python -m app.cli sync-reports --from-month 2026-06 --to-month 2026-08
```

Первая команда скачивает официальную региональную таблицу; вторая получает федеральные обзоры за **исторические месяцы**, приведённые только как пример. Для новых данных используйте опубликованные месяцы. Если сайт Банка России временно недоступен — используйте официальный XLSX, сохранённый в `downloads/cbr_volume.xlsx`:

```bash
python -m app.cli validate-regions --file downloads/cbr_volume.xlsx
python -m app.cli import-regions --file downloads/cbr_volume.xlsx
```

Для отключённой сети/демонстрации можно импортировать `python -m app.cli demo` (все синтетические значения помечены **ДЕМО**) или `python -m app.cli seed-official` (локальный проверенный вручную набор, **не** онлайн-синхронизация). **Не выдавайте эти данные за свежую загрузку с сайта ЦБ.**

Для проверки API/интерфейса:

```bash
python scripts/smoke.py --base-url http://127.0.0.1:8000
```

Если обновляете существующий v0.4, сначала сделайте резервную копию `mortgage.db`, `downloads/`, `config/targets.json`, `.env`. Не копируйте новые файлы поверх действующей базы. Модель БД в v0.5 не требует новых колонок, но для боевой эволюции необходимы миграции (Alembic).

## Настройка официального REST API Банка России

```bash
python -m app.cli discover --query ипотеч
```

Сверьте найденные `publication_id`, `dataset_id`, `measure_id`, методологию и единицы измерения с [документацией ЦБ](https://www.cbr.ru/statistics/data-service/APIdocumentation/). Запишите утверждённые идентификаторы, например, по схеме:

```json
{
  "targets": [
    {"publication_id": 123, "dataset_id": 456, "measure_id": -1, "from_year": 2022}
  ]
}
```

**123/456 здесь исключительно иллюстрация схемы, не реальные идентификаторы ЦБ.** Удалите их, подставив проверенные значения. `measure_id = -1` допустим лишь для набора без измерений `type != 1`. Допускается разовый импорт CLI: `python -m app.cli sync --publication-id ID --dataset-id ID --from-year 2022 --to-year 2026`. Импорт фиксирует успешную/ошибочную попытку. Если `targets.json` пуст — планировщик обновляет XLSX и обзоры, **но не импортирует ряды Data Service**. Это намеренно: банковская аналитика не должна автоматически выбирать непроверенную семантику.

## Развёртывание в Docker (закрытый контур / стенд)

1. Создайте `.env` в корне с двумя **разными** случайными секретами `POSTGRES_PASSWORD` и `ADMIN_TOKEN`, каждый длиннее 32 символов; `python -c "import secrets;print(secrets.token_urlsafe(48))"`.
2. Запустите `docker compose up -d --build`.
3. Приложение доступно только на `127.0.0.1:8000` хоста. Для внешней публикации настройте **отдельный HTTPS reverse proxy**, ограничение частоты запросов и политики доступа (пример требований ниже). **Не публикуйте порт 8000 напрямую в интернете.**
4. Проверьте `docker compose ps`, `docker compose logs -f api scheduler`, `curl -fsS http://127.0.0.1:8000/api/v1/readiness` и `/api/v1/data-quality`.
5. Для первого импорта при необходимости: `docker compose exec scheduler python -m app.cli sync-regions-online`; для текущих месяцев — `sync-reports --from-month ... --to-month ...`.

В production `APP_ENV=production` требует сильный `ADMIN_TOKEN`, отключает Swagger и внутренний веб-планировщик; обновления выполняет контейнер `scheduler`. Контейнеры приложения работают непривилегированным пользователем, без дополнительных Linux capabilities и с файловой системой только для чтения (кроме специального volume с XLSX и tmpfs). PostgreSQL хранит данные в volume `postgres_data`. `GET /api/v1/health` — проверка доступности приложения; `GET /api/v1/readiness` — проверка БД. Внешняя доступность ЦБ **не** входит в readiness.

Администратор запускает асинхронную проверку:

```bash
curl -X POST http://127.0.0.1:8000/api/v1/refresh \
  -H 'Content-Type: application/json' -H "X-Admin-Token: $ADMIN_TOKEN" -d '{}'
```

Подробные ошибки закрытого журнала: `GET /api/v1/admin/sync-runs` с `X-Admin-Token`. Публичный `/api/v1/sync-runs` отдаёт статусы и счётчики, скрывая внутренние исключения. Кнопки ручного обновления на публичном production-портале скрыты.

**Обязательно прочитайте** [эксплуатационный чек-лист](docs/BANK_DEPLOYMENT_CHECKLIST.md) и [проверки конкурсного решения](docs/ACCEPTANCE_V05.md) перед пилотом.

## Границы точности и применения

1. Источник национальных рядов — HTML «Обзор рынка ипотечного жилищного кредитования»; это **не** то же самое, что REST Data Service. Каждый тип импорта явно выделен.
2. `cbr_xlsx` — архив официальных региональных таблиц; XLSX «количество» и «ставки» допускает скачивание/просмотр, но пока не импортирует как проверенные отдельные ряды. Ретроспективные методологические изменения ЦБ требуют сверки.
3. В репозитории нет свежего проверенного файла Банка России, сетевой end-to-end проверке через контейнер разработчика препятствует ограничение исходящего интернета. **Запуск у пользователя с реальным доступом к ЦБ обязателен.**
4. Прогноз — алгоритмический расчёт по трём простым моделям (сезонное повторение, скользящее среднее, тренд), без учёта внешних макроэкономических факторов. Данные со временем могут быть пересмотрены. Эвристические границы **не** гарантируют калиброванной вероятности покрытия, отсутствует оценка причинного влияния ключевой ставки. Запрещено использовать его для автоматического принятия кредитных решений.
5. Код — пригодная для пилотной интеграции **основа**, а не окончательная банковская продукционная платформа: понадобятся HTTPS/SSO и RBAC, управление секретами, CI/CD, SAST/DAST, миграции, тестирование на реальных выгрузках, резервное копирование с восстановлением, мониторинг/оповещения, нагрузочное тестирование и формальная приёмка ИБ.

Источники: [основной раздел ипотечной статистики ЦБ](https://www.cbr.ru/statistics/bank_sector/mortgage/), [официальный REST Data Service](https://www.cbr.ru/statistics/data-service/), [API-документация](https://www.cbr.ru/statistics/data-service/APIdocumentation/).
