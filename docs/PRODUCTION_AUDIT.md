# Mortgage Analytics Hub 0.5.1 — заключение по аудиту кода

Дата: 25 октября 2026 г. Цель: устранить воспроизводимые ошибки, укрепить защиту загрузчиков и сохранить поведение конкурсного прототипа.

## Что проверено

- Ручной просмотр FastAPI-маршрутов, авторизации, импорта Data Service, HTML и XLSX, модели БД, планировщика, прогнозирования, интерфейсного JavaScript и Docker-конфигурации.
- Автоматические тесты: **40 passed** под Python 3.12; проверены повторный импорт, откат некорректного пакета, безопасность административных действий, данные качества, региональный анализ и прогноз.
- Проверка синтаксиса Python и JavaScript. Формат методов `/publications`, `/datasets`, `/measures` и `/data` сопоставлен с официальной документацией Банка России; актуальные идентификаторы REST-рядов не установлены в `config/targets.json`.

## Исправленные дефекты

| Приоритет | Проблема | Исправление |
| --- | --- | --- |
| Высокий | Docker API с `read_only: true` не имел записываемого каталога XLSX, поэтому защищённый запрос ручного обновления мог завершиться ошибкой записи | Добавлен общий с scheduler volume `/service/downloads` |
| Высокий | API и отдельный scheduler могли одновременно обновлять таблицы, вызывая гонки уникальности и конфликтующие ревизии | Общая PostgreSQL advisory lock на период ETL; локальный mutex для SQLite |
| Средний | Лимит размера REST/HTML проверялся после скачивания ответа целиком | Размер проверяется при потоковом чтении; слишком большие ответы отвергаются |
| Средний | Дубли одного ряда и месяца в одной пачке могли искажать счётчики и историю | Идентичные дубли пропускаются, конфликтующие отвергаются |
| Средний | Журнал качества не находил месячные операции `schedule:YYYY-MM` | Исправлен фильтр источника |
| Низкий | Нечисловые и бесконечные значения были допустимы в прямом вызове модуля прогноза | Добавлена проверка конечности |
| Низкий | Произвольный текст из исходного CSV мог интерпретироваться как формула табличного редактора | Экранирование опасных начальных символов |
| Низкий | Диапазоны версий позволяли незаметно установить новую несовместимую основную комбинацию библиотек | Закреплены проверенные прямые зависимости, тестовые вынесены из Docker requirements |

## Что остаётся обязательным до production

**Статус: усиленная пилотная версия; промышленный допуск не подтверждён.** Локальные тесты не доказывают отсутствие всех багов.

1. С реальным доступом к `cbr.ru` провести end-to-end импорт последних выпусков, проверить актуальность и все три вкладки регионального XLSX. Утвердить проверенные `publication_id`/`dataset_id`/`measure_id` для нужных рядов Data Service и методологию.
2. Проверить сборку и запуск Docker Compose с PostgreSQL, корректность volume, recovery при аварии и совместимость с фактическим сетевым прокси. Выполнить smoke и нагрузочные испытания.
3. Настроить HTTPS, WAF/rate limits, сетевые ACL, персональные служебные учётные записи и RBAC вместо общего токена; добавить ротацию секретов и аудит доступа.
4. Ввести Alembic-миграции, стратегию резервного копирования/восстановления, метрики и алерты по пропущенным публикациям, статусам очереди и ошибкам источников.
5. Ввести SBOM, автоматический аудит зависимостей, CI/CD со SAST/DAST и пентест. Docker base image желательно фиксировать по digest.
6. Отдельно валидировать качество прогнозов по горизонту, регионам и стресс-периодам. Текущие интервалы эвристические, макрофакторы отсутствуют, автоматические решения по кредитам запрещены.

## Рекомендованный порядок демонстрации

1. На подготовленном **официальном** наборе показать обзор и первоисточники.
2. Выбрать регион, валюту и месяц; проверить рейтинг и сравнение.
3. Показать выбор модели прогноза по MAE, сценарий и предупреждение об интервале.
4. Показать журнал операций, SHA-256 и индикаторы качества; повторить импорт для подтверждения отсутствия дублей.
5. Продемонстрировать административную защиту и дорожную карту банковского внедрения.

Запуск тестов: `python -m pip install -r requirements-dev.txt`, затем `python -m pytest -q`.
