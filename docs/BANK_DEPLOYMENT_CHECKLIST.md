# Чек-лист для пилота в банковском контуре (v0.5)

Статус на момент передачи: **не пройдена банковская приёмка**. Никаких утверждений о выполнении обязательных стандартов информационной безопасности или сертификации нет.

## Перед демонстрацией

- [ ] Выполнены `pytest`, `scripts/smoke.py`, проверка четырёх маршрутов интерфейса.
- [ ] В базе есть свежая (проверенная на официальных источниках) статистика, пометка `demo` не используется как фактическая.
- [ ] Успешно сверены регионы, единицы измерения и опубликованный период.
- [ ] Настроены проверенные ID для Data Service. Если каталог не доступен, факт отсутствия REST-рядов отражён в журнале.
- [ ] Проверены исходные XLSX реального выпуска (все 3 листа) и федеральные обзоры текущего/предыдущих месяцев.
- [ ] Проведён реальный повтор импорта; наблюдения не задублированы.
- [ ] Проверены частичный отказ и последующий успешный повтор синхронизации.

## До эксплуатации с внешним доступом

- [ ] HTTPS reverse proxy с управляемыми сертификатами, заголовками HSTS и rate limits; не публиковать Docker порт приложения напрямую.
- [ ] Сетевой ACL исходящего трафика ограничивает допустимые внешние назначения (cbr.ru); прокси не допускает редиректов на посторонние хосты.
- [ ] SSO/сервисные учётные записи и RBAC для операторских действий; заменить общий токен на контролируемые отдельные учётные данные.
- [ ] Секреты вынесены из Compose `.env` в корпоративное хранилище секретов; настроена ротация.
- [ ] Управляемые миграции БД, индексы/планы запросов, резервные копии PostgreSQL; проверено **восстановление**, определены RPO/RTO.
- [ ] Централизованные логи и корреляция операций, неизменяемый журнал операторских действий, алерты о пропущенных обновлениях, аномалиях и ошибках источника.
- [ ] SAST/DAST, зависимостный аудит, SBOM, закреплённые digests базовых образов и обновления по CVE.
- [ ] Пентест и разбор модели угроз (особенно XLSX, серверная интеграция и импорт данных).
- [ ] Регламент качества: дата среза, допустимая задержка публикации, сопоставимость выпуска/объёма и слои методологии.
- [ ] Нагрузочное тестирование и горизонтальное масштабирование с отдельным планировщиком, кэшем и ограничениями на экспорт.
- [ ] Контроль разрешений на использование брендов/источников, правовая оценка условий публикации, согласование модели ответственности и локальных требований регулятора.
- [ ] Валидация прогнозной модели на rolling/expanding origin и режимах рыночного стресса, документация сценариев, отдельное согласование модельного риска.

## Технические ограничения текущего релиза

- API статистики для публичного чтения без аутентификации, что соответствует конкурсному требованию. Защиту от abuse необходимо реализовать на шлюзе.
- Нет полноценной банковской модели пользователей и ролей (лишь общий административный токен). Планировщик отрабатывает раз в час и делает ретраи, но не является брокером заданий с exactly-once семантикой.
- `Base.metadata.create_all()` — удобен для первичного старта, не заменяет управляемые миграции.
- Снимок `cbr_snapshot` — только зафиксированные ручные сведения. Отдельно от live-данных.
- Кросс-проверка 2% — аналитическая диагностика, не нормативный тест сопоставимости показателей.
