# Приёмка конкурсного прототипа v0.5

1. `python -m pytest -q` — все тесты должны проходить; не подменять сетевые данные синтетическими в обычной БД.
2. `python -m uvicorn app.main:app --host 127.0.0.1 --port 8000`; проверить `/api/v1/health`, `/api/v1/readiness`, `/api/v1/data-quality`, `/api/v1/series`.
3. Проверить 4 маршрута приложения: обзор, регионы, прогноз, журнал. Кнопки навигации ведут на страницы; пункт «Документация API» удалён из меню (локальный Swagger доступен по `/docs`).
4. На графиках проверить zoom, pan, range slider, PNG; по каждому ряду — CSV.
5. Пополнить хранилище официальным источником и проверить единицы измерения, дату наблюдения, первоисточник, региональный рейтинг/сравнение.
6. Открыть журнал, проверить статусы и счетчики. Публичный журнал не должен включать подробные ошибки, пароли или пути серверной ФС.
7. Проверить `GET /api/v1/source-artifacts`: SHA-256, размер и `retrieval`, а при изменении прошлого наблюдения `GET /api/v1/admin/revisions` с токеном. Повторно импортировать один XLSX: увеличивается `unchanged`, не увеличивается количество наблюдений. При испорченном XLSX старые корректные значения сохраняются.
8. `data-quality` показывает возможные пропуски месяцев, устаревшие серии, офлайн-снимок и сводную сверку разных источников.
9. В production (`APP_ENV=production`) запуск без безопасного `ADMIN_TOKEN` завершается ошибкой, Swagger выключен, ручное обновление не показывается гостям.
10. В отдельном scheduler настроены проверенные Data Service IDs или отчётливо указано, что REST target-набор пока пуст. Проверить статус monthly run и retry на частичном отказе.
11. Прогноз явно помечен неофициальным, таблица показывает MAE, историю и сценарные допущения; при коротком/прерывистом ряде возвращается 422.
12. В реальной инфраструктуре **дополнительно** протестировать доступность ЦБ, Docker build, TLS-прокси, секреты, резервные копии и нагрузку. Офлайн-тесты не являются эквивалентом такой приёмки.
